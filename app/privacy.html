OnCall privacy policy

Applies to a self-hosted OnCall server and its Alexa+ add-on. The person or team running the server is the data controller.

What OnCall stores

Everything is kept in one SQLite database on the operator's own server:

  • Operational evidence: request and error samples, deployment records, alerts, incidents, approvals, executions, audit timeline and handoff reports.
  • Account linking: OAuth client records, single-use authorization codes and access/refresh tokens. Codes and tokens are stored only as SHA-256 hashes.
  • Voice approvals: a hash of each one-time code, its expiry and attempt count. With a paging channel configured, the code itself is never stored or returned in a response. In the sandbox with no pager, the demo shows the code on screen and keeps it until it expires.
  • Agent conversation threads, when the optional investigation agent is used.

OnCall does not store your name, email address, voice recordings, location or Amazon account details. Alexa+ sends OnCall only the tool request and an access token.

What leaves the server

  • Paging, only if the operator sets ONCALL_NOTIFY_URL: the incident title, service, a link and, for voice approval, the one-time code, all sent to that endpoint.
  • Investigation, only if the operator sets ONCALL_BEDROCK_MODEL_ID: incident evidence is sent to Amazon Bedrock in the operator's AWS account.
  • Public status, only if ONCALL_PUBLIC_STATUS=true: a redacted, read-only view of health, error rates, release identifiers and incident titles.

Nothing is sold, shared for advertising or sent to the OnCall authors.

Retention and deletion

Data stays until the operator deletes it. Expired authorization codes and service tokens are pruned automatically. To unlink Alexa, disable the add-on in the Alexa app. The operator can also revoke tokens at /revoke or delete the oauth_* rows.
